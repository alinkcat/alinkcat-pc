## 一、项目总览

**定位**：PC 与手机联动的效率工具——PC 端设计个性化"主题包"（`.alc`），实时推送到 Android 手机渲染；含硬件监控、媒体控制、快捷面板、主题市场、用户体系。
**版本**：v0.1.0-beta（公测 1.0 已上线）→ **2.0 公测开发中**（标语：让灵感 2 分钟落地）。
**协议**：本项目代码仅供学习参考，未经授权不得用于商业用途。

### 仓库结构

```
alinkcat/
├── alinkcat-pc/          # PC 桌面端（Tauri 2 + React 19 + TS + AntD6 + zustand + Rust）
├── alinkcat-android/     # Android 移动端（Kotlin + Jetpack Compose + Material3 + OkHttp）
├── alinkcat-module/      # Root 扩展模块（Magisk / KernelSU，POSIX shell，骨架状态）
├── docs/                 # 云端 AI 网关后端需求（v3 草案）
├── res/                  # 2.0 公测介绍文案
└── 顶层 *.md             # README / 2.0 介绍与更新日志 / 2.0 开发规划 / i18n 方案 / 语言包指南
```

### 技术栈矩阵

| 平台 | 技术 |
|---|---|
| PC 桌面端 | Tauri 2 + React 19 + TypeScript + Ant Design 6 + zustand；Rust 后端（WebSocket 服务器、硬件监控、媒体控制） |
| Android 移动端 | Kotlin + Jetpack Compose + Material3 + OkHttp |
| 通信协议 | JSON-RPC 2.0 over WebSocket（PC 端端口 9527） |
| 云端后端 | Spring Boot（独立仓库，本地联调 `localhost:8080`） |
| Root 模块 | POSIX shell（Magisk v20.4+ / KernelSU / APatch 建议兼容） |

### 端到端数据流

```
PC 编辑器（构建主题）→ theme.json + 资源 → 打包 .alc（ZIP+Base64+SHA-256）
        ↓ WebSocket 分块推送（64KB/块、断点续传、失败重试、JSON-RPC 2.0）
Android 接收 → 解压 → 校验 → 渲染（17 种控件）
运行时数据流：PC Rust 侧推 monitor.update（1s）与 media.update（2s，变化才推）→ 手机端控件订阅渲染
```

### 3.4 关键实现要点

- **主题组件实际 18 种**（代码），文档称 15 种（缺 battery/card/weather——文档过时）
- **API 核心机制**：所有 JSON 请求经 `apiFetch` → Rust 命令 `api_request`（reqwest 代理绕 CORS，伪装 Chrome UA）；响应 `snakeToCamel` 递归转驼峰（**后端字段必须下划线命名**）；multipart 上传走浏览器原生 fetch
- **鉴权**：JWT 存 localStorage，解析 `exp` 提前 30s 刷新（互斥防并发）；401 → refresh → 重试一次 → 失败清 token 派发 `auth:expired`（每会话弹一次）
- **后端地址切换**：开发者模式（设置页标题连点 5 次解锁，可自定义 host/port）→ `VITE_API_BASE_URL`（dev=localhost:8080 / prod=top.atqx.cn）→ 默认 http://top.atqx.cn
- **编辑器**：手机模型默认横屏 16:9、AI 面板默认收起、快捷键（Delete/Ctrl+C/V/D/方向键）、图层 Z-Order、统一撤销、自动保存（localStorage）；加新组件要同步 4 处：`Editor/types/index.ts`、`editorStore.makeWidget`、Rust `manager.rs` 校验白名单、文档
- **资源管理**：Base64 data URL 提取为文件 + 内容 hash 去重（assets/icons 分目录）+ 孤儿清理
- **打包**：`zip::ZipWriter` Deflated → Base64 + SHA-256，`.alc` 扩展名
- **AI**：`useAICommands.ts` 指令式（types/ai.ts 定义 **15 种**指令，README 称 8 种已过时；`generate_full_theme`/`batch` 破坏性指令需确认）+ `ai_chat_stream.rs` 流式（SSE 经 Tauri 事件 ai-chunk/ai-done/ai-error 转发）；默认对接 `https://api.deepseek.com/v1`
- **i18n**：zh-CN 常驻兜底改 **en-US 兜底**；语言包 JSON 动态导入（localStorage `ilinkcat_custom_languages`）；antd locale 联动
- **OAuth**：GitHub OAuth（OAuthLogin/OAuthCallback），Rust 侧 `oauth_callback_server.rs` 监听 **127.0.0.1:9528** 收 `?token=`
- **WS 握手（3 阶段）**：Phase1 握手 10s 超时（配对码错误 -32001/超时 -32002/同名设备踢旧 -32003）→ Phase2 双向消息泵（AckBus 消费确认）→ Phase3 断线清理订阅（无订阅自动停调度器）
- **媒体控制仅 Windows**（SMTC + QQ音乐/网易云窗口标题兜底正则），非 Windows 运行时返回"不支持"
- **托盘**：关闭窗口 = 隐藏到托盘（prevent_close），菜单「显示主界面/退出应用」

- **模型**：`Theme → Page[] → Widget[]`（sealed Widget）；兼容新旧两套 page schema；`Widget.fromJson` 17 分支 + 别名兼容（icon→Button、snippet-list→StickyNote、gridW→colSpan）

### 4.4 通信协议（JSON-RPC 2.0）

- HTTP 报文 `{code,message,data,timestamp}`（成功码 200；业务错误 -32020 拒绝/-32021 失败/-32602 参数非法）
- WebSocket：handshake（配对码）/ `theme.push.start|chunk|complete|cancel` / `theme.switch` / `monitor.*` / `action.execute`
- **推送状态机 7 态**：IDLE→PENDING_CONFIRM→RECEIVING→COMPLETED/FAILED/CANCELLED/INTERRUPTED；逐 chunk 回执、SHA-256 校验、解压、**zip-slip 防护**、存储空间 ×1.5 检查、断点续传（.part）
- **重连**：主界面连接仅启动失败重试 3 次 ×2s（无退避、无断线重连）；**渲染页用独立 WebSocket**（设备名加 `" (Display)"` 后缀防互踢）+ 5s 定时重连；握手协议补偿（`entered` 标志，握手成功后补发 enter+subscribe+media.get_current）
- **扫码配对**：二维码格式 `alinkcat://connect?ip=&port=&pair=`；Android 解析兼容 JSON / URL / 纯文本三格式（ConfigScreen.applyScanContent）
- **认证现状**：ProfileScreen 注释"无登录概念：所有功能本地可用"；天气云端接口统一走 **X-API-Key** 鉴权；`DeviceInfoProvider`/`security-crypto`/proguard 保留规则为登录时代未清理遗留

## 五、alinkcat-module（Root 扩展模块）

> 状态：**骨架**（16 个文件，仅 1 个提交 `f0e61f5`，从未构建过，`dist/` 不存在）

### 定位
已 Root 设备上的"能力通道层"：为普通 App 无法访问的系统级操作提供 CLI 入口。`module.prop`：`id=alinkcat_module`、`minMagisk=20400`（Magisk v20.4+）。

### 目录结构与职责

| 路径 | 职责 |
|---|---|
| `bin/alnkcat_helper` | 统一 CLI 入口（**POSIX shell 脚本**，非二进制），命令：`version/capabilities/daemon/monitor/action/config/secret` |
| `scripts/shell/monitor.sh` | 读 `/sys`、`/proc`：CPU 使用率(/proc/stat)、温度(/sys thermal_zone)、频率、电池电压/温度/电流/电量、GPU(kgsl→mali0 多路径)、内存(/proc/meminfo)，全部带兜底 |
| `scripts/shell/action.sh` | 动作：`shell`(sh -c)/`service`(start/stop/restart)/`settings put`/`brightness`(写 backlight sysfs)/`input keyevent`/`pm` |
| `scripts/shell/config.sh` | 读写 `module.conf`（grep 读、sed 写） |
| `scripts/service.sh` | 开机拉起 daemon（sleep 空循环，无 socket） |
| `scripts/post-fs-data.sh` | 空占位 |
| `scripts/uninstall.sh` | 杀进程、清理文件 |

### ⚠️ 已知缺陷与风险（上线前必修）

1. **customize.sh 随机密钥生成失效**：引用不存在的 `config/module.conf.example`（cp 被吞）；sed 匹配 `SECRET=` 而实际 key 是 `MODULE_SECRET=` → 安装后密钥保持默认 `change_me`
2. **`secret` 命令无鉴权**：`bin/alnkcat_helper secret` 直接 `echo "$MODULE_SECRET"`，任何可调用的 App 都能读出密钥，进而 `action shell` 拿 root 执行任意命令
3. **文档与代码偏差**：README 宣称的 `power.sh`（性能调度）、`doc/PROTOCOL.md`、`bin/alnkcat_daemon`、`module.conf.example` **均不存在**；daemon 无 socket 监听；性能调度/应用内广播/护眼色温均为规划
4. **Android 端 RootHelper 完全未开发**：全仓库无任何 `su`/`alnkcat_helper` 调用代码；现有 PC↔Android 联动与 root 无关（WebSocket JSON-RPC）
