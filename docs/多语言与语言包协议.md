## 一、轨道一：App UI 语言包（本期开发）

### 1.1 语言来源与注册

| 来源 | 位置 | 注册方式 | 标记 |
|---|---|---|---|
| 原生英文 | `res/values/strings.xml` | 系统自动 | 兜底基准，永不缺席 |
| 原生中文 | `res/values-zh/strings.xml` | 系统自动 | — |
| 内置动态语言 | `assets/langpacks/{code}.json` | 首启扫描 LanguageManager | Built-in |
| 导入语言包 | `filesDir/langpacks/{code}.json` | SAF 导入 + `index.json` 登记 | Imported，可删除/导出 |

**首启语义（已决策）**：严格英文。首次启动一律英文界面；语言选择持久化于 SharedPreferences（`ilinkcat_prefs` / `app_language` key，值：`system`/`en`/`zh`/`pack:{code}`）。语言选择器中的 "System Default" 在此语义下等于 English（首启默认值即 `en`，与 "System Default" 殊途同归）。

### 1.2 语言包信封格式 v1

```json
{
  "code": "ja-JP",
  "label": "日本語",
  "platform": "android",
  "version": 1,
  "keyCount": 173,
  "minAppVersion": "1.0.0",
  "resources": {
    "app_name": "iLinkCat",
    "tab_themes": "テーマ",
    "connected_pc": "%1$s%2$s に接続済み",
    "delete_theme_confirm": "「%1$s」を削除しますか？"
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | ✓ | BCP-47 风格语言码（`ja-JP`、`ko-KR`、`en`）。导入时作为包身份与文件名 |
| `label` | ✓ | 母语显示名，语言选择器展示用 |
| `platform` | ✓ | 固定 `android`。**PC 包（无此字段或非 android）导入时明确报错**，不静默失败 |
| `version` | ✓ | 包格式版本，当前 `1`。见第三节版本策略 |
| `keyCount` | ✗ | 导出方写入的 key 总数，导入侧用于核对与覆盖率计算；缺省以实际解析数为准 |
| `minAppVersion` | ✗ | 预留字段。要求 App 版本高于当前时拒绝导入并提示升级 |
| `resources` | ✓ | **扁平 key-value**。key 与 `strings.xml` 的 `name` 同名（零映射层） |

**key 约定：**
- 扁平同名 key：`resources.tab_themes` ↔ `<string name="tab_themes">`
- **append-only 承诺**：key 只增、不改名、不删除。这是旧语言包在新版 App 上「覆盖率下降但永不损坏」的根基
- 占位符使用 **Android 位置格式**（`%1$s`、`%2$d`），与 strings.xml 语义直接对齐；**不采用** PC 端的 `{{var}}` 风格（两端正交，各自贴合本地体系）

**与 PC 端格式的关系：** 信封结构（`code/label/resources`）与 PC 语言包同构，但 key 集合与占位符风格不同。两端各自维护基准，不追求单一 key 集。

### 1.3 校验规则（导入时）

| # | 规则 | 失败处理 |
|---|---|---|
| 1 | UTF-8 编码 | 拒绝整包 |
| 2 | 文件 ≤ 2MB | 拒绝整包 |
| 3 | `platform == "android"` | 拒绝整包，提示「这是 PC 端语言包」 |
| 4 | `version` ≤ 当前支持版本（1） | 拒绝整包，提示「请升级 App」 |
| 5 | `minAppVersion` ≤ 当前 App 版本 | 拒绝整包，提示升级 |
| 6 | key 数 ≤ 500；value ≤ 500 字符 | 拒绝整包（防异常包） |
| 7 | 占位符与英文基准逐 key 比对 | **不一致的 key 单独回退**，不阻塞整包；确认弹窗列出问题 key 数 |
| 8 | 缺 key | 允许导入；确认弹窗显示覆盖率（X/总数），缺 key 回退英文 |

### 1.4 导入 / 导出流程

**导入**（设置页 → 语言分区）：
1. SAF `ACTION_OPEN_DOCUMENT`（mime `application/json`）选择文件——零存储权限
2. 解析 + 上表 8 项校验
3. 覆盖率预览弹窗：`已翻译 X/173 · 问题 key Y 个（将回退英文）`
4. 确认 → 写入 `filesDir/langpacks/{code}.json`，`index.json` 登记元数据
5. 可选「立即切换」→ 重建 Activity 激活

**导出**（两个出口，格式与导入完全一致，自产自销闭环）：
- **英文模板**：全 key、英文值（文件名 `{appVersion}_template.json`）→ 给翻译者
- **当前语言完整包**：含 `code/label/keyCount` → 给分享/备份

同 `code` 重复导入 = 覆盖更新（弹窗确认）。

### 1.5 运行时解析链

```
Compose: stringResource(id) / LocalContext.getString(id)
   │  (attachBaseContext 注入 Context 包装层 → 自动路由，调用点零迁移)
   │
   ├─ 当前语言 = 动态包（内置或导入）
   │    ├─ PackResources.getString 命中内存 Map → 返回译文（String.format 应用占位符）
   │    └─ 缺 key ──────────→ 英文原生资源（值永远来自 values/）   ← 永不空
   │
   └─ 当前语言 = en / zh（原生）
        └─ attachBaseContext(createConfigurationContext(locale))
             → values-zh / values 原生资源

服务层（非 Compose 类）: LanguageManager.getString(resId, vararg args)
```

**实现机制（已落地，与初稿不同）**：放弃「172 处 `stringResource` 调用点全量迁移」方案，改为 **Resources 包装层拦截**：
- `AlinkcatApplication.attachBaseContext` 同步初始化 LanguageManager（读 SharedPreferences + 加载动态包）
- `MainActivity` / `ThemeRenderActivity` 各自 `attachBaseContext` 注入：原生语言用 `createConfigurationContext(locale)` 切 locale；动态包用 `LanguagePackContextWrapper`（`ContextWrapper` + `Resources` 子类 `PackResources`）重写 `getString`/`getText` 查表
- Compose 的 `stringResource` 底层走 `LocalContext.current.resources`，经包装层自动路由，**无需改动任何 UI 调用点**
- 服务层（`PushReceiveManager`、`ThemeRenderViewModel` 等非 Compose 类，其持有的 applicationContext 不经 Activity 注入）显式用 `LanguageManager.getString(resId, args)`；其内部回退用与当前选择一致的 locale 上下文（en/zh），动态包期间回退英文
- 动态包激活期间强制 locale=en（保证兜底路径确定性），RTL 包同时切换 `LayoutDirection`
- `MainActivity` 与 `ThemeRenderActivity` 共享同一 app 级单例，两屏语言一致；语言切换后监听 `recreateTick` 触发 Activity 重建即时生效

### 1.6 存储布局

```
filesDir/
└── langpacks/
    ├── index.json          # [{code, label, keyCount, importedAt, source: imported|builtin}]
    ├── ja-JP.json
    └── ko-KR.json
assets/langpacks/           # 内置动态语言发行通道（随 APK）
└── {code}.json
```

`index.json` 只登记用户区包；内置包每次首启扫描重新注册（便于版本升级时同步更新内置语言）。

### 1.7 URL 下载导入

语言包列表页提供「从 URL 下载」入口：
- 仅允许 `http://` / `https://`，其他 scheme 直接拒绝
- 限制响应体 ≤ 2MB（流式读入，边读边检查，超出即中止并删除临时文件），跟随重定向 ≤ 3 次
- 下载后走与 SAF 导入相同的校验 + 覆盖率弹窗流程，不直接落盘

## 二、轨道二：主题包多语言（仅锁协议，本期不动代码）

### 2.1 .alc 结构

```
theme.json            ← 完全不变（作者语言原文，最终兜底）
locales/              ← 可选目录；缺席 = 单语言主题（对作者零成本）
  ├── ja-JP.json
  └── en.json
```

**为什么是覆盖文件而不是内联进 theme.json：** 内联意味着 17 种控件 × 十几个文本字段（`label/text/title/snippets[]`…）全部要改成「字符串或对象」双态判断，侵入面极大；覆盖文件方案下 theme.json 解析代码**一行不动**，本地化是解析后的独立 overlay pass（`ThemeI18nApplier`，按控件 id 定位、字段级合并，约百行），渲染器无感。

### 2.2 locale 文件格式

```json
{
  "code": "ja-JP",
  "label": "日本語",
  "version": 1,
  "theme":    { "name": "オーロラ", "description": "…" },
  "pages":    { "page-home": { "label": "ホーム" } },
  "widgets": {
    "widget-1": { "label": "電池" },
    "widget-2": { "text": "こんにちは" },
    "widget-3": { "snippets": [ { "id": "s1", "label": "挨拶", "content": "…" } ] }
  }
}
```

- 寻址：页面/控件按 **id**（与 App 端 `Widget.fromJson` 的 `fallbackId: widget-{index}` 兜底约定一致）
- 数组字段（`snippets[]`、QuickAction cells）按元素 `id` 对位
- 只写需要覆盖的 key；字段级合并，未覆盖字段保持原文

### 2.3 内容轨兜底链（与 App 轨语义不同！）

```
App 当前语言（如 zh-CN）
  → locales/zh-CN.json 存在？ 用它
  → locales/zh.json（主码）存在？ 用它
  → theme.json 原文（作者语言）            ← 最终兜底
```

> **关键语义差异**：主题内容缺译时回退到**作者的语言**，而不是 App 界面语言，更不是英文。
> 「英文界面 + 中文主题」「日文界面 + 英文主题」都是合法组合；原文是内容轨的最终真理，不做机器转换。

### 2.4 主题包级版本字段（预留）

| 字段 | 位置 | 说明 |
|---|---|---|
| `defaultLanguage` | theme.json（可选） | 声明作者语言，缺省=原文即默认 |
| `version` | 每个 locale 文件 | 与 App 语言包同策略（见下节） |

### 2.5 PC 端适配清单（后续排期引用）

1. **`snippets[]` / QuickAction cells 等数组元素生成稳定 id**（编辑器侧生成并持久化）——⚠️ 最重要的前置要求，overlay 按 id 寻址依赖它
2. theme.json 增加可选 `defaultLanguage` 字段
3. 编辑器属性面板文本字段加多语言入口（复用 PC 已有 i18n 语言列表）
4. 导出 .alc 时写 `locales/{code}.json`（只含已翻译字段）
5. 后期增强：编辑器语言切换实时预览；AI 面板「一键批量翻译生成 locales」（协同亮点）
6. 推送侧**零改动**：locales/ 随 .alc zip 走现有 `theme.push.*` 通道，接收端解压即得

### 2.6 渲染端落地（未来开发时）

- `ThemeI18nApplier.apply(theme, localeJson)`：解析后、渲染前的纯数据 pass
- 语言选择跟随 App 当前语言（含动态包的 `code`），支持精确码→主码降级
- 已知边界：主题自定义字体可能缺目标语言字形（如像素字体仅 CJK 字库）——PC 预览时提醒，协议层不管

## 三、版本策略（三轨通用）

| 层 | 版本载体 | 当前 | 策略 |
|---|---|---|---|
| App 语言包格式 | 信封 `version` | 1 | 只有**破坏性变更**才 bump；v1 存续期内仅追加可选字段（org.json 忽略未知字段，旧 App 读新包不炸）；`version > 支持值` 拒绝导入 |
| App key 集 | strings.xml | 194 行 | **append-only**：只增不改名不删；旧包 = 覆盖率下降，永不破坏 |
| 主题 locales | 各文件 `version` | 1 | 同 App 语言包策略；双端共用本文档作协议基准 |

导出包内嵌 `keyCount` 与导出时 App 版本，便于诊断覆盖率问题。

## 四、协议预留：language.push.*（本期不实现）

复用现有 WebSocket JSON-RPC 2.0 通道（与 `theme.push.*` 同构，仅预留方法名与语义，不开发）：

```
language.push.start    → { code, label, keyCount, size, sha256 }
language.push.ready    → 确认接收
language.push.chunk    → base64 分块（64KB，逐块 ack）
language.push.complete → SHA-256 校验 → 写入 filesDir/langpacks/ → index 登记
language.push.cancel   → 任一侧取消
```

后期 PC 端加一条 Rust 命令（如 `language_push_to_device`）即可打通「PC 导入语言包 → 推送手机」。
注意：App 语言包本就是小文件（≤2MB），不需要断点续传的 `.part` 机制，协议比 theme.push 简单。

## 五、边界与非目标

- 桌面启动器图标 label 走 manifest 资源体系，不受动态语言包影响
- v1 不支持 plurals（现有 strings.xml 无复数资源）；占位符仅位置格式
- 不做运行时机器翻译；缺译即回退，不猜测
- App 轨与内容轨**不共享** key 空间与文件（一个管 UI 壳、一个管主题内容，生命周期与作者都不同）
- PC `{{var}}` 与 Android `%1$s` 占位符风格**不统一**（有意为之，各自贴合本地体系；文档明示防止后续误改）
